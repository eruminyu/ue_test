2.2 MCP와 연결

  • MCP(Model Context Protocol)는 AI가 외부 프로그램의 기능을 "툴"로 불러 쓰게 하는 공개 규약이다. UE 5.8 에디터에는 MCP 서버가 들어 있어서, 에디터가 켜지면 8000번 포트(127.0.0.1)에서 서버가 시작된다. Claude Code(Anthropic의 코딩 에이전트)는 이 서버에 HTTP로 붙어서 에셋 생성, 속성 설정, 컴파일 같은 에디터 기능을 툴 호출로 실행한다. 서버가 PC 안에서만 열리므로 Claude Code도 같은 PC에서 돌아야 한다.
  • 에셋은 모두 MCP로 만들었다. git 커밋, 스크린샷 PNG 변환, 엔진 툴 소스 읽기는 Claude Code의 셸과 파일 도구로 했다.
  • Claude Code는 저장소의 .mcp.json으로 서버에 붙는다. 세션을 저장소 루트에서 열어야 이 파일이 읽힌다. 첫 세션은 상위 폴더에서 열어 연결이 안 됐고, 사람이 루트에서 세션을 다시 열어 연결을 승인했다.
  • MCP 툴은 처음부터 다 보이지 않고, 메타 툴 3개로 필요할 때 찾아 쓴다. list_toolsets로 툴셋 52개의 목록을 보고, describe_toolset으로 사용법을 읽고, call_tool로 실행한다. 툴셋마다 툴이 여러 개 있고, BlueprintTools 한 툴셋에만 53개가 있다.

2.5 툴을 쓰는 요령

  • 그래프는 DSL로 한 번에. BlueprintTools의 S-expression DSL(write_graph_dsl)로 함수와 이벤트 그래프를 통째로 썼다. GA_Attack 콤보 그래프는 한 번 쓰기로 노드 49개가 만들어졌다. 어빌리티 태스크의 비동기 출력 핀은 (:OnCompleted …) 같은 연속 블록으로 이어 붙였다.
  • DSL로 안 되는 곳은 노드 API로. Enhanced Input 이벤트의 Started 핀처럼 DSL로 고를 수 없는 연결은 create_node → connect_pins → set_pin_value로 만들었다. DSL을 다시 써도 이 노드들은 지워지지 않는 것을 확인했다.
  • 속성은 ObjectTools로. GE의 모디파이어, 큐, 인스턴스드 서브오브젝트 배열(GE 컴포넌트), IMC 매핑, 위젯 슬롯 레이아웃, 컴포넌트 템플릿 값 모두 set_properties로 넣었다. 넣은 뒤에는 get_properties로 다시 읽어 비교했다.
  • 반복은 ProgrammaticToolset로 묶기. 태그 24개(단계 2), GE 10개(단계 4), 입력 이벤트 노드 15개(7-4)처럼 반복되는 호출은 짧은 Python 스크립트 하나로 묶어 왕복 횟수를 줄였다. 이 샌드박스는 툴 호출만 묶을 수 있어서 판정은 "성공"으로 기록했다.
  • 큰 출력은 파일로. describe_toolset 결과(최대 약 278KB)는 파일로 받아 필요한 부분만 추렸다. 스크린샷 base64(약 1.8MB)는 스크립트 안에서 바로 파일로 저장해 컨텍스트를 아꼈다.

  • 큐 노티파이 생성과 부모 변경, 템플릿에서 Niagara 시스템 생성
  • BP 그래프: 함수, 함수 오버라이드, 어빌리티 태스크, 커스텀 이벤트, 디스패처, 컴포넌트 바인딩 이벤트
  • 변수(기본형, 구조체, 오브젝트, 배열, 로컬), 컴포넌트 추가
  • IA, IMC 매핑(defaultKeyMappings.mappings), UMG 트리와 레이아웃
  • 맵 복제와 액터 배치, WorldSettings, 프로젝트 설정, PIE 시작·종료, GAS 인스펙터, 로그

우회해서 됨

  • 클래스 참조 변수·파라미터 → 클래스 리터럴 핀, InputTag 기반 발동
  • BP 인터페이스 추가 → SlateInspectorToolset UI 자동화
  • 새 레벨 생성 → 엔진 템플릿 맵 Template_Default 복제
  • enum 배열 리터럴 → DSL로 빈 MakeArray 연결 후 set_pin_value
  • 태그 컨테이너 리터럴 → MakeGameplayTagContainerFromTag 노드
  • PIE 스크린샷 → SlateInspector.Screenshot을 파일로 저장

사람이 함

  • BP 템플릿 프로젝트 생성, 설치 스크립트 적용 확인(준비 단계, 이전 Claude Code 세션과 함께)
  • 저장소 루트에서 Claude Code 세션 다시 열기(MCP 연결)
  • 플레이 테스트로 입력, 콤보, 무적, 부활 확인
  • 에디터에서 블루프린트를 직접 고친 일은 없음

MCP로 못 함

  • 몽타주 섹션·노티파이 읽기와 쓰기(CompositeSections, Notifies)
  • Python unreal 모듈 사용(샌드박스 허용 모듈: json, math, re, time, datetime, copy)
  • PIE 게임 뷰포트에 키 입력 보내기
  • GameplayCueToolset으로 새로 만든 큐 조회(에디터 큐 라이브러리가 갱신되지 않음. 플레이에서는 문제 보고 없음)

4막힌 곳과 푼 방법

다음 작업자가 같은 곳에서 시간을 쓰지 않도록, 증상과 원인과 대응을 정리했다.

증상원인대응
동시 호출하자 응답이 다른 호출의 결과로 돌아옴에디터 하나에 붙은 MCP 서버에 여러 요청이 동시에 들어감(실제 실행은 됨)에디터당 호출 1개. 서브에이전트도 순차로만 실행
계획서의 "Python 대체"가 불가ProgrammaticToolset은 툴 호출을 묶는 용도라 unreal 모듈을 import할 수 없음전용 툴 조합과 UI 자동화로 대체. 안 되면 사람에게 넘김
클래스 참조 변수를 만들 수 없음. UClass 오브젝트 변수는 타입이 integer로 깨짐클래스 참조(TSubclassOf) 타입을 만드는 변수 툴이 없음(add_variable은 기본형 7종과 구조체 5종, add_struct_variable은 구조체, add_object_variable은 오브젝트 참조만)클래스 리터럴 핀으로 쓰고, 발동은 AbilityTags의 InputTag로
첫 PIE에서 어빌리티가 REINST_GA_Attack_C_5로 부여되고 ensure 발생클래스 변수 대신 GA·GE의 CDO를 오브젝트 참조로 넣었다. BP를 재컴파일하면 엔진은 옛 CDO를 REINST_ 임시 클래스로 옮기고 새 CDO를 만든다. 그래서 옛 CDO를 가리키던 참조에서 GetClass를 부르면 REINST_ 클래스가 나온다. 클래스 참조는 원래 클래스를 가리키므로 영향이 없다CDO 참조를 모두 클래스 리터럴로 교체. GA를 다시 컴파일한 뒤에도 정상임을 확인
몽타주 섹션과 노티파이를 읽을 수 없음ObjectTools가 해당 속성을 노출하지 않음템플릿 노티파이가 BPI_Attacker 메시지를 보낸다는 점을 이용해, 노티파이 추가 대신 인터페이스 구현으로 설계 변경
BP 인터페이스를 추가할 툴이 없음ObjectTools는 Blueprint를 항상 CDO로 바꿔 다룸SlateInspector로 Class Settings UI 조작. Details 목록을 따로 Observe해야 Add 버튼이 잡힘
DSL 작성 실패멤버 변수는 맨 이름으로 못 읽음, bool 변수 bIsDead의 게터는 GetIsDead, 태그 컨테이너 리터럴 불가, +는 리터럴이 붙어야 문자열 연결노드 타입을 먼저 조회. 실패한 쓰기는 스냅샷 롤백돼 부분 노드가 남지 않음
괄호가 든 이벤트 이름을 DSL에 쓸 수 없음OnHealthChanged(DemoAbilitySystem)의 괄호를 토크나이저가 분리이벤트 이름을 따옴표로 감쌈
읽기만 했는데 템플릿 BP 12개가 dirtyfind_node_types, get_node_type_pins가 내부적으로 임시 노드를 만들었다 지움템플릿은 저장하지 않는 것이 원칙이다. 이번에는 에디터를 끌 때 12개가 다시 저장됐지만 .gitignore 대상이라 저장소에는 영향이 없다
새로 만든 큐를 GameplayCueToolset이 못 찾음에디터 큐 라이브러리가 큐 생성 전에 초기화됨에셋 태그(GameplayCueName)로 등록을 확인하고 DefaultGame.ini에 GameplayCueNotifyPaths를 추가했다. 그 뒤 조회 툴이 큐를 찾는지와 큐 재생은 따로 확인하지 않았다(플레이 중 문제 보고는 없음)
캡처에서 캐릭터가 구겨진 포즈CaptureViewport는 PIE 중에도 애니메이션이 없는 에디터 월드를 찍음PIE 화면은 SlateInspector 위젯 스크린샷으로
SlateInspector로 보낸 키가 게임에 안 들어감게임 뷰포트가 Slate 키보드 포커스를 받지 못함. 백그라운드 에디터는 약 3fps로 스로틀입력이 필요한 검증은 사람 플레이로
우려했지만 문제가 없었던 것. 계획서는 "MCP로 만든 Enhanced Input 이벤트 노드가 바인딩 없이 조용히 안 불린다"는 보고를 경고했다. 이번 방식(노드 생성 → Started 핀 연결 → 전체 컴파일)에서는 5개 입력이 모두 정상 동작했다. GE 컴포넌트 같은 인스턴스드 서브오브젝트 배열과 IMC 매핑도 ObjectTools로 문제없이 편집됐다.

5팀 프로젝트에 쓰는 방법 제안

이번 데모에서 MCP는 "정해진 사양을 에셋으로 옮기는 일"에 가장 강했다. 태그, 스탯 테이블, GameplayEffect, 큐, 입력 매핑, UI 배치, 레벨 배치처럼 속성 위주인 에셋은 전용 툴로 막힘 없이 만들어졌고, 넣은 값을 다시 읽어 검증할 수 있었다(단계 4의 GE 12개와 큐 3개에 약 6분. 사람 작업과 시간을 비교하지는 않았다). 규칙이 분명한 어빌리티 그래프도 DSL로 한 번에 썼다. 반대로 클래스 참조 변수, BP 인터페이스, 몽타주 노티파이처럼 구조를 정하는 작업은 전용 툴이 없어서 설계를 우회하거나 에디터 UI 자동화로 처리해야 했다. 이번에는 우회로 모두 해결했지만, 팀 작업에서는 사람이 먼저 만들어 두는 편이 안전하다. 또 MCP로는 PIE에 키 입력을 넣을 수 없어서 입력이 필요한 동작 확인은 사람이 플레이로 했다. 그래서 팀에서는 사람이 뼈대(클래스 변수, 인터페이스, 노티파이가 들어간 몽타주)와 사양 문서를 먼저 만들고, AI가 MCP로 데이터 에셋과 그래프를 채우는 분업을 권한다. 사람은 AI가 남긴 단계별 기록표와 커밋 단위로 검토하고 플레이로 확인한다.

운영 규칙

  • 에디터 하나에 에이전트 하나. 같은 에디터에 동시에 호출하면 응답이 섞인다. 병렬 작업은 에디터(또는 PC)를 나눠서 한다.
  • 사양 문서를 먼저. 수치, 태그 이름, 에셋 이름을 표로 정해 두면 AI가 그대로 만들고 철자까지 검증한다. 이번에도 태그 24개를 추가한 뒤 목록을 다시 읽어 확인했다.
  • 단계마다 strict 컴파일, 다시 읽기, 커밋. read_graph_dsl은 EI 이벤트 핀 같은 일부 연결을 보여 주지 않으니, 컴파일이 통과해도 핵심 연결은 get_node_infos로 다시 읽는다. 되돌리기 쉽게 커밋을 잘게 나누고, 바이너리 에셋은 Git LFS로 관리한다.
  • 공용·템플릿 에셋은 읽기만. 읽기 툴만 써도 dirty가 될 수 있으니 저장 범위를 작업 폴더로 한정한다.
  • 클래스 참조는 리터럴이나 사람이 만든 변수로. CDO 참조로 우회하지 않는다.
  • 기록을 남긴다. "MCP로 됨 / 우회 / 사람 / 못 함"을 계속 쌓으면 어디까지 AI에 맡길지 팀이 판단할 근거가 된다.

맡기기 좋은 일과 사람이 할 일

AI + MCP에 맡기기 좋음사람이 먼저 하거나 직접 할 일
태그, DataTable, CurveTable 같은 데이터 에셋의 대량 생성게임플레이 구조 결정(베이스 클래스, 인터페이스, 클래스 변수)
GE 수치, 코스트·쿨타임, 큐 연결 같은 반복 설정몽타주 노티파이, 애니메이션 편집
사양이 명확한 BP 함수와 어빌리티 그래프 초안새 C++ 클래스(팀 합의가 필요한 영역)
IMC 매핑, UMG 트리와 레이아웃, 레벨 액터 배치입력이 필요한 플레이 검증, 조작감과 밸런스 조정
컴파일·인스펙터·로그를 이용한 상태 점검최종 저장 범위 확인과 푸시

다음에 해 볼 것

  • Epic 공식 스킬 플러그인(unreal-engine-skills-for-claude-code)을 설치하고 같은 작업의 품질과 속도를 비교한다. 이번에는 설치되지 않아 에디터 내장 스킬(BlueprintBasicsSkill)만 썼다.
  • 사람이 클래스 변수와 인터페이스 뼈대만 만든 상태에서 나머지를 MCP로 채우는 분업을 실제 기능 하나로 시험한다.
  • MCP 서버 쪽에 PIE 입력 주입이나 몽타주 편집 툴이 추가되는지 핫픽스마다 list_toolsets로 확인한다.

재현하려면

  • UE 5.8(Templates and Feature Packs 포함)과 Visual Studio C++ 빌드 도구가 필요하다. C++ DemoAttributeSet 하나를 컴파일해야 하기 때문이다.
  • Claude Code는 에디터와 같은 PC에서 돌린다(데스크톱 앱 Code 탭 로컬 세션 또는 CLI). MCP 서버가 127.0.0.1에서만 열리므로 클라우드 세션은 붙을 수 없다.
  • Third Person BP 템플릿으로 ActionDemo를 만들 때 Variants에서 Combat, Platforming을 고른다. 그다음 DemoKit/install.ps1 -Build를 실행하고 OpenEditor_EN.bat으로 영어 에디터를 연다.
  • 저장소 루트에서 Claude Code 세션을 열고 unreal-mcp 연결을 승인한 뒤, docs/demo/03-mcp-build-plan.md 순서대로 진행하라고 지시한다. 자세한 설치 절차는 docs/demo/01-setup-windows.md에 있다.
